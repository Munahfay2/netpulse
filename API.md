# NetPulse API

Base URL (local dev): `http://localhost:8000`. Interactive Swagger docs are
auto-generated by FastAPI at `/docs` and a raw OpenAPI schema at
`/openapi.json` — this document is a human-readable companion, not a
replacement.

All responses are JSON unless noted (the USSD endpoint returns plain text,
per the Africa's Talking USSD contract).

## Auth

### `POST /api/auth/demo-login`
No body required. Creates (if needed) and returns a token for the seeded
demo account — this is what the frontend's "Demo Login" button calls.

```json
{ "token": "…", "user": { "id": "...", "email": "demo@netpulse.africa", "full_name": "...", "isp_name": "..." } }
```

### `POST /api/auth/login`
```json
{ "email": "you@isp.africa", "password": "..." }
```
Returns the same shape as demo-login, or `401` on bad credentials.

## Network overview

### `GET /api/network/overview`
Powers the Live Network map. Returns every location with its OLTs and their
live health rollup.
```json
[
  { "id": "LOC-...", "name": "Njoro", "region": "Rift Valley",
    "olts": [ { "id": "OLT-003", "name": "Njoro OLT-003", "status": "critical",
                "online": 0, "degraded": 0, "offline": 12, "active_incidents": 1 } ] }
]
```

## Devices

### `GET /api/devices?olt_id=&health=&page=&page_size=`
List devices, optionally filtered by OLT or health (`healthy` | `degraded` |
`offline`), paginated.

### `GET /api/devices/{device_id}`
Single device detail.

## Telemetry

### `GET /api/telemetry/{device_id}?limit=50`
Recent telemetry points for a device (for the device detail chart).

### `POST /api/telemetry`
The integration point for a **real** telemetry agent (see
`ARCHITECTURE.md`). Runs the same detection/correlation pipeline the
simulator uses.
```json
{
  "device_id": "CPE-0001",
  "router_status": "online",
  "wan_status": "down",
  "lan_status": "normal",
  "internet_reachable": false,
  "latency_ms": 0,
  "packet_loss_percent": 100
}
```

## Incidents

### `GET /api/incidents?status_filter=`
List incidents, optionally filtered by status.

### `GET /api/incidents/{id}`
Full incident detail including telemetry-derived facts, probable cause with
reasons, recommended checks, and the full event timeline.

### `PATCH /api/incidents/{id}`
```json
{ "status": "In Progress" }
```
Valid statuses: `Detected`, `Investigating`, `Assigned`, `In Progress`,
`Resolved`, `Closed`.

### `POST /api/incidents/{id}/assign`
```json
{ "technician_id": "TEC-..." }
```
Assigns a technician, moves the incident to `Assigned` if it wasn't already
further along, and sends the technician SMS alert.

## Fault simulation

All of these are `POST` with no body and change the in-memory simulator
scenario, which the telemetry loop picks up on its next tick (every
`TELEMETRY_INTERVAL_SECONDS`, default 5s):

| Endpoint | Effect |
|---|---|
| `/api/simulator/normal` | Baseline healthy telemetry |
| `/api/simulator/single-failure` | One device goes fully unreachable |
| `/api/simulator/high-latency` | One OLT's devices see high latency + moderate loss |
| `/api/simulator/packet-loss` | One OLT's devices see severe packet loss |
| `/api/simulator/wan-failure` | One OLT's devices lose WAN |
| `/api/simulator/olt-failure` | Same effect, framed as an OLT-level failure |
| `/api/simulator/area-outage` | The busiest OLT's devices all lose WAN — the main demo scenario |
| `/api/simulator/restore` | Clears the scenario and restores all telemetry to healthy |
| `GET /api/simulator/status` | Current scenario + target OLT |

## USSD

### `POST /api/ussd`
Form-encoded, matching the Africa's Talking USSD webhook contract:
`sessionId`, `phoneNumber`, `text` (accumulated `*`-separated choices). An
additional optional `customer_id` field lets the browser-based USSD
simulator drive a specific seeded customer's session without needing a real
phone number to match. Returns plain text prefixed `CON` (continue) or
`END` (terminate the session).

## SMS webhooks

### `POST /api/sms/callback`
Receives inbound SMS from Africa's Talking (e.g. a customer texting
support) and logs it as a ticket.

### `POST /api/sms/delivery-report`
Receives delivery-status updates from Africa's Talking and updates the
matching notification's status where it can be matched.

## Demo utilities

### `GET /api/health`
Liveness check.

### `POST /api/demo/reset`
Wipes all incidents, telemetry, tickets, notifications, and network data,
then re-seeds from scratch. Used by the Settings page's "Reset Demo" button.
